# AGENTS.md

Guidance for AI agents and contributors working in this repository.

## Project Overview

`@keeratita/heic-converter` is a TypeScript library that converts `.heic`/`.heif` images to standard web formats (**JPEG, PNG, WebP, AVIF, SVG**) in the browser or Node.js.

Key design constraints:

- **CSP-compliant**: libheif C++ is compiled to WASM with Emscripten using `-s DYNAMIC_EXECUTION=0` — no `eval()`/`new Function()` is ever generated. Do not remove this flag.
- **Zero runtime dependencies**: do not add any.
- **Isomorphic**: browsers do full conversion via Canvas; Node.js decodes raw RGBA only (`convertHeic` throws there — no Canvas, encode externally e.g. `sharp`).
- **libheif-based**: decoding via `libheif` + `libde265`, cross-compiled with Emscripten inside Docker.

## Architecture & Key Facts

- **Conversion flow** (`convertHeic`, `src/index.ts`): normalize → validate `quality` (0–1) → pick decoder → `initialize()` → `decode()` → **free the library-owned decoder before `renderAndEncode`** (decoded pixels are a standalone copy), again in `finally`; `free()` is idempotent and never called on a user-injected decoder.
- **Decode strategy selection**: injected `options.decoder` wins; else `nativeDecode: true` (opt-in, default off) selects `NativeHeicDecoder` (`src/wasm/native.ts`, `createImageBitmap` + OffscreenCanvas readback behind the `DecodedImage` contract) unless the realm refused; else a fresh `LibheifDecoder` per conversion. The policy lives in one helper (`nativeDecodeEligible`) consulted by both selection and the `convertMany` pool gate — `preserveExif: true` or `applyOrientation: false` pins libheif, and only an eligible batch bypasses the pool. **Only an environment-class failure marks the realm** (`decoder_init_failed` from initialize = missing platform APIs → sticky + one-time breadcrumb warn); decode-class failures (corrupt file, size cap, transient 2D pressure) and `aborted` re-throws never mark — one bad upload must not cost the page native speed. A failed *fetch* of the native chunk degrades like the EXIF chunk: convert via libheif with a one-time `Messages.NativeChunkLoadWarning` naming `dist/native-*.mjs`, without caching a refusal. Native decode caps the bitmap at duplicated copies of the decode caps (`MAX_NATIVE_DECODE_DIMENSION` 16384/side pinned equal to `MAX_CANVAS_DIMENSION`, and `MAX_NATIVE_DECODE_PIXELS` 64 MP total pinned equal to `kMaxDecodePixels` in `main.cpp` — both pins parse the sources in `native-decoder.test.ts`; the duplicates keep the lazy chunk out of the render graph) **before** allocating canvas + `ImageData` — an uncapped container-declared size would OOM outside the WASM heap. Blob-backed input is copied to detach only when `SharedArrayBuffer`-backed (Blob construction rejects SAB views; normal buffers are not double-copied). The fallback checks `throwIfAborted` before paying for the WASM load. Native output is upright (platform applies EXIF/irot/imir) and fires progress only at completion.
- **Decoder lifecycle**: fresh `LibheifDecoder` *per conversion* so concurrent calls never share WASM state. `freeSharedDecoder()` is a compat **no-op** — do not reintroduce a globally shared instance. Sanctioned exception: `convertMany({ reuseDecoders: true })` leases/returns via the module-private `DecoderPool` — one item at a time per instance, bypassed when the caller injects `decoder`. **Faults**: a WASM trap poisons emmalloc's arena, so `decode()` wraps any non-`HeicConverterError` throw as `decode_failed` (original on `cause`) and records the instance in `src/wasm/fault.ts`; `DecoderPool.release()` frees a poisoned instance instead of parking it and returns its slot. This is what makes SECURITY.md's typed-error promise true rather than incidental.
- **WASM wrapper** (`build-wasm/wrapper/main.cpp`): embind `HeicDecoder.decode(string, progressCb)` → `{ width, height, data, orientation?, exif? }` (`data` = interleaved RGBA; `exif` = normalized `"Exif\0\0" + TIFF` APP1). libheif builds some error strings from raw container bytes, so `sanitizeDecoderDetail()` strips control chars and clamps to 200 chars before they reach `error.message` (consumers log it; the demo writes it to the DOM). `LibheifDecoder.decode()` returns **owned copies** — never WASM-heap views — so results survive `free()` and concurrent decodes can't corrupt each other. `initialize()` memoizes module loading; the glue arrives via dynamic `import()` so it ships as a lazy chunk.
- **Orientation policy**: libheif applies `irot`/`imir` at decode (dimensions come back swapped) — those files must never be rotated further. EXIF tag 274 (`DecodedImage.orientation`, IFD0 only, bounds-checked) is reported **only when no `irot`/`imir` fourcc appears anywhere in the container** — worst case "not rotated", never double-rotation. `convertHeic` renders a pending orientation as one composed `setTransform` matrix; resize sizes on display dimensions (axes swapped for 5–8). `applyOrientation: false` keeps stored geometry. Regression fixtures: `test/fixtures/exif-orientation-6.heic` (EXIF-only → `orientation: 6`, portrait output) and `test/fixtures/irot-orientation-6.heic` (both signals → upright, **no** pending orientation).
- **Progress callbacks**: libheif ≥ 1.21 ships the start/on/end hooks natively (`image-items/grid.cc`); `build-scripts/patch-libheif.py` patches older trees and auto-skips newer ones. The pinned 1.23.6 normally no-ops the patch.
- **EXIF preservation** (`preserveExif`, default `false` — privacy: EXIF carries GPS): the block is re-injected only for JPEG (APP1 after APP0; payloads beyond the 65,533-byte segment limit skipped) and PNG (`eXIf` before the first IDAT, CRC32 in `src/render/exif.ts`); WebP/SVG ignore it. The raster is already upright, so `normalizeOrientationTag` rewrites tag 274 to `1` before injection (kept verbatim with `applyOrientation: false`). Both injectors are **fail-safe** — unparsable encoder output, malformed blocks, or size overflow return the original bytes (metadata loss, never corruption). A failed fetch of the lazy `./exif` chunk likewise degrades to no-EXIF with a **one-time** `console.warn` naming `dist/exif-*.mjs` (test hook `__resetExifChunkWarning`) so a partial upload isn't indistinguishable from a file with no Exif item.
- **AVIF capability probe**: `render/canvas.ts` probes a 1×1 AVIF `toBlob` once per environment (module-cached; test hooks `__resetAvifProbe`, `AVIF_INDETERMINATE_COOLDOWN_MS`). **Tri-state**: `false` only for a definitive refusal, `true` for real bytes, `undefined` when indeterminate (starved `toBlob` callback within a 5 s deadline, a null-blob or throwing probe — both are encoding failures, not support verdicts — or `createCanvas` failure). Only booleans are cached; an indeterminate attempt clears the cache but is honoured for a 10 s cooldown so a burst on a starved host shares one window. Consumers gate on `=== false` — AVIF is never denied on a guess (caching a false negative was the old bug). `assertEncodeCapability(format)` runs **before** paying for a decode; `renderAndEncode` re-checks defensively and the `blob.type` re-check is the authority in the indeterminate case.
- **Batch/worker plumbing**: `convertMany`/`convertManyInWorker` share `runBoundedBatch` (`src/batch.ts`). Abort semantics: an aborted signal wins over item-failure aggregation; a batch completed before the abort returns its results; with `continueOnError` an abort stops new items and fills not-yet-started entries with `aborted` errors. Worker-side abort terminates workers immediately; the per-URL semaphore never over-admits (a cancelled waiter leaves the queue without granting its place). The semaphore **pools live workers**: one that answered a clean `ok: true`+blob is parked with listeners detached and adopted by the next `grant()` instead of paying boot again; timeout/abort/transport-error/`ok: false` always terminate; at most `MAX_PARKED_WORKERS` (2, evicting the oldest) stay warm per URL because each holds a grown WASM heap. Idle slots keep parked workers warm for `WORKER_POOL_IDLE_MS` (5 s — sequential batch items arrive within a microtask) then terminate them. **The protocol is request-correlated**: each request carries a monotonic `id`; replies must echo it, and `progress`/`result` messages with a missing or stale `id` are ignored — this is what stops a duplicate/late reply from a previous lease settling the adopted worker's next caller. The timeout diagnostic counts ignored results and flags adopted leases (a `self.close()`-ing script now stalls a lease to `timeoutMs` — no dead-worker event exists on the `Worker` API, so detection is by diagnostic, not retry). Test hooks: `__resetWorkerPool()` (top-level export in `src/worker.ts`) and `__semaphoreTestHooks`. **User-authored worker scripts must keep a persistent `onmessage`, never `self.close()` after replying, and echo `id`** — API.md documents this contract; `docs/worker.js` is the canonical reference (the sandbox E2E and the Pages demo both serve it, and `docs-sync.test.ts` pins the README/API.md/JSDoc examples byte-equal to it modulo the import specifier). **Progress is one shared gate** (`createProgressGate`, `src/progress.ts`, used by the in-process and worker paths): percentages are clamped, the `100` event is withheld until the item succeeds, and sub-100 values stay live even for items that ultimately fail. Option validation (`src/validate.ts`) runs on the main thread in **all four** entry points; the worker APIs additionally validate `maxConcurrentWorkers` and `convertMany` validates `concurrency` — both integers 1–64 (`MAX_BATCH_CONCURRENCY`; values above the ceiling reject with `invalid_concurrency`, they are never clamped, and each runner boots a full WASM decoder) — and `timeoutMs` (finite ≥ 0, a per-call deadline including queue wait). The worker result message's `blob` field is `Blob | string | ArrayBuffer` (name kept for protocol compatibility).
- **Bundle composition**: only the main-thread in-process path is eager — entry + shared chunks ≈ 20.6 KB min / 8.0 KB gz, Terser-minified (`tsup.config.ts`; `terser` is a dev dep, so zero runtime deps stay). Four lazy chunks behind dynamic `import()`: the Emscripten glue (`import('./wrapper/heic-decoder.js')`, ~34 KB, first decode), the Web Worker (`import('./worker')`, ~6.9 KB, first worker call — the entry's thin wrappers map a failed chunk fetch to `HeicConverterError('worker_load_failed')`), the EXIF injectors (`import('./exif')` inside `withExif` after its early return, fetched `.catch(() => null)` → degrades to no-EXIF), and the native strategy (`import('./wasm/native')`, ~1.6 KB, first `nativeDecode: true` — the refusal verdict lives inside the chunk; the one-time chunk-*load-failure* warning is logged by the entry, so its text lives in `Messages`). Message strings follow the **which-chunk-throws rule**: `Messages` is one object literal esbuild cannot tree-shake per property, so worker-only text lives in `src/messages/worker.ts`; `WorkerChunkLoadFailed` stays in `Messages` because `src/index.ts` throws it before the worker chunk exists, while validator strings live in the worker module. `test/unit/bundle.test.ts` enforces this mechanically (dynamic edges in both ESM and CJS passes, per-chunk floors, 23 KB eager ceiling, **no static chunk-to-chunk edges among the lazy chunks**, published-chunk completeness, `dist/` WASM byte-identity, first-decode ceilings) and skips without `dist/` but **never on CI**. Do not add a static `import` of `./worker`, `./exif`, or `./wasm/native` to the entry or the render stage.
- **WASM build** (`build-scripts/build-wasm.sh`): pins `libde265 1.1.3`, `libheif 1.23.6`, `emscripten/emsdk:3.1.56`. libde265 ≥ 1.1.0 is CMake-only (`emcmake cmake`). Sources are the `build-wasm/src/` submodules, verified against pinned tags. Libraries compile at **`-Oz`**; the **emcc link stays `-O3`** (see size below). libheif is configured with `-DLIBHEIF_BOX_EMSCRIPTEN_H` (drops its dead `EMSCRIPTEN_BINDINGS` block) and every codec `option()` OFF using the names 1.23.6 declares (`WITH_AOM_*`, `WITH_JPEG_*`, `WITH_OpenJPEG_*`, `WITH_X264`, `WITH_OpenH264_*`, `WITH_X265`, `WITH_DAV1D`, `WITH_SvtEnc`, `WITH_RAV1E`); `WITH_LIBSHARPYUV` stays at its `ON` default (inert). The build **fails if `CMakeCache.txt` resolves any third-party codec** other than libde265. Flags that must be preserved: `-s DYNAMIC_EXECUTION=0`, `-s ALLOW_MEMORY_GROWTH=1`, `-s EXPORT_ES6=1`, `-s MODULARIZE=1`, `-s ENVIRONMENT="web,worker,node"`, `-s MALLOC=emmalloc`, `-s FILESYSTEM=0`, `--bind`, link `-O3`. Cache stamps hash the script itself, so editing any build flag forces both libraries to rebuild.
- **WASM size** (binary tuned 0.5.1, unchanged since; JS figures re-measured after the 0.5.2 review fixes): first-decode payload **316,402 gz / 255,399 br**; packaged binary 814,197 raw / 296,479 gz / 237,521 br; glue chunk 33,902 raw / 11,874 gz; eager JS 20,574 raw / 8,049 gz. Shipped levers: `-Oz` compile + `-O3` link, `-DLIBHEIF_BOX_EMSCRIPTEN_H`, `-s FILESYSTEM=0` (module byte-identical — decoding is memory-only), `-s MALLOC=emmalloc`, post-link `wasm-opt -O3 --zero-filled-memory`. Measured dead ends — do not retry: emcc **link-level** size flags (`-O2`/`-Os`/`-Oz`/`-flto`) produce a smaller module that **fails to instantiate** under `--bind`+MODULARIZE+EXPORT_ES6; post-link `--minify-imports*` renames imports the glue references; post-link `-Oz`/`--strip-target-features` shrink raw but *increase* gz/br; `--gc-sections` collected nothing. The whole glue is 11.9 KB gz, so no glue-level trick can be worth much. Re-measure against a newer emsdk before chasing more.
- **Env detection**: `render/canvas.ts` supports `OffscreenCanvas`, then `HTMLCanvasElement`, else a clear error.

## Conventions

- **Conventional Commits** (`feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert`, optional scope), enforced by husky `commit-msg`; `pre-commit` runs lint + typecheck.
- TypeScript, strict-ish; keep the public API small and backwards compatible (e.g. `freeSharedDecoder` kept as a no-op). Comments should be concise — state the why, not the what.
- Unit tests: `test/unit/**/*.test.ts` (Vitest, Node). **Tests are typechecked too** via `tsconfig.test.json` — it must keep overriding the base config's `exclude: ["test"]` or `npm run typecheck` is silently vacuous (verified by canary).
- **Documentation that duplicates a code fact is tested, not trusted**: `readme.test.ts` and `api-doc.test.ts` diff the error-code tables in `README.md`/`API.md` against the `HeicConverterErrorCode` union and fail if any entry-point export is undocumented in `API.md`. `API.md` is the exhaustive reference, the README's API section the working one — keep both current when the public surface changes. Public JSDoc for the worker APIs lives on the wrappers in `src/index.ts` (that is what `dist/index.d.ts` ships).
- CI (`ci.yml`): `npm ci --ignore-scripts` → gates (`verify:wasm`, `check:scripts`) → `npm ci` (the gate run must not execute install hooks; the real install follows, so the allowlist check is a pre-flight not a bypass) → lint → typecheck → build → coverage → Playwright E2E, on pushes/PRs to `main`. A path-gated `wasm-provenance` job rebuilds the decoder in Docker from the pinned submodules and diffs the sha256s against `wasm-artifacts.json` (accepted flakiness risk: Docker/emsdk drift surfaces as PR-time failures to rerun). `.github/CODEOWNERS` requires review on build-critical paths (its handle needs maintainer confirmation). `demo-pages.yml` splits build (contents: read) from deploy (the only job holding `pages`/`id-token`), so `npm ci` never runs under deploy credentials; the site moves as an artifact. `publish.yml` splits so the token-holding job never installs: `verify` builds and uploads `dist/`; `publish` downloads those exact bytes, requires tag == version and ancestor of `main`, publishes with `--registry` pinned on the CLI, then runs `verify:provenance`.

## Gotchas

- **Never edit generated files**: `src/wasm/wrapper/heic-decoder.js`, `src/wasm/public/heic-decoder.wasm`, `dist/`, `build-wasm/src/` (submodule C++). Regenerate via `npm run build:wasm`.
- **Submodule drift**: bump `LIBDE265_VERSION`/`LIBHEIF_VERSION` **and** `git checkout` the tag in the submodule; `build-wasm.sh` verifies and fails on drift. If artifacts look unchanged after a bump, check the submodule commit.
- **`npm run build:wasm` needs Docker + network** and is slow; run it only when changing `main.cpp`, the build script, or lib versions.
- **Two separate "builds"**: `build` (TS → `dist/`) vs `build:wasm` (C++ → WASM); most work needs only the former. **Always `npm run build` before running suites after a checkout or merge** — a stale `dist/` JS chunk paired with the current WASM fails as the misleading `module.HeicDecoder is not a constructor` (`bundle.test.ts`'s byte-identity check covers the WASM, not the JS chunks).
- `.wasm` is externalized (`tsup.config.ts` `external`) and served separately; keep `locateFile`/`wasmBinary` compatibility.
- Tests that decode real HEIC files require `src/wasm/public/heic-decoder.wasm` to exist.
- **WASM build changes must be executed, not just measured.** Every rejected size flag in 0.5.1 built a *smaller* binary that only failed at `WebAssembly.instantiate()`. Adopt nothing until the real-decode integration tests, `wasm-golden.test.ts` (exact decoded RGBA per fixture + mutated-input outcomes) and the browser E2E pass against the rebuilt pair — glue + WASM come from one `emcc` invocation, always replace both together, then `npm run wasm:hashes`.
- **Never deep-compare large buffers in tests.** `toEqual` on ~800 KB Buffers walks them structurally (~1.1 s idle, over the 5 s timeout under the parallel suite). Use `a.equals(b)` with sha256s in the message; hash pixel data and compare digests like `wasm-golden.test.ts`.
- **`vi.mock` intercepts only the first of two *racing* dynamic imports** of the same path (vitest 5.0.3 limitation; sequential imports and real ESM caching are fine). Batches exercising a mocked lazy chunk must use `concurrency: 1` or seed the registry with a static import of the mocked path.
- **The real-WASM suites must never skip green.** `integration.test.ts`, `decoder.test.ts`, `wasm-golden.test.ts` skip only outside CI — keep the `describe.skipIf(!hasArtifacts && !isCI)` shape (per-test `it.skipIf` isn't enough: an all-skipped suite skips `beforeAll` and exits 0) and keep `ci.yml`'s artifact `test -f` checks in sync with `hasArtifacts`.
- **Never put a double quote inside the `bash -c "..."` block in `build-wasm.sh`** — it silently truncates the container script (docker exits 0, build stops before the link; the `Build complete!` sentinel now fails such runs). Use single quotes inside that block.
- Keep the library environment-agnostic at import time: no top-level browser-only references (`document`, `Blob` usage is guarded).
- **Never disguise a string to silence a scanner.** The package's three scanner signals — the glue `fetch()`es `heic-decoder.wasm`, the SVG namespace URL, Terser-minified output — are correct-but-harmless. Document them in the README's _Supply chain & trust_ table; fragmenting or hex-encoding literals is how malware behaves.
- **Dev-tree install scripts are the only code-execution surface** (no runtime deps; `npm ci --ignore-scripts` is unusable because esbuild's postinstall links its binary). Allowed packages are pinned by name **and version** in `build-scripts/install-scripts.json`; CI fails on drift, and non-registry resolutions (`file:`/`link:`/git) are rejected outright. To add one legitimately: read its script, `npm run check:scripts -- --write`, commit the diff.
- **A falsification that terser can delete is not a falsification.** When proving the bundle guard bites, inject leaked text on a *live throw path* (e.g. inside a validator's `throw`), not as dead code — minification removes the latter and the assertion passes vacuously.
