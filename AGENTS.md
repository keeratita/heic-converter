# AGENTS.md

Guidance for AI agents and contributors working in this repository.

## Project Overview

`@keeratita/heic-converter` is a TypeScript library that converts `.heic`/`.heif` images to standard web formats (**JPEG, PNG, WebP, AVIF, SVG**) in the browser or Node.js.

Key design constraints:

- **CSP-compliant**: The libheif C++ code is compiled to WebAssembly with Emscripten using `-s DYNAMIC_EXECUTION=0` — no `eval()` or `new Function()` is ever generated. Do not remove this flag from the WASM build.
- **Zero runtime dependencies**: The package has no production dependencies. Do not add any.
- **Isomorphic**: Runs in both browsers (full conversion via Canvas) and Node.js (raw RGBA decoding only — Canvas encoding is unavailable and `convertHeic` throws on the backend).
- **libheif-based**: HEIC decoding is done by `libheif` (with `libde265`), cross-compiled to WASM via Emscripten inside Docker.

## Architecture & Key Facts

- **Conversion flow** (`convertHeic` in `src/index.ts`): normalize input → validate `quality` (0.0–1.0) → pick decoder (user-injected `options.decoder` or a fresh `LibheifDecoder`) → `initialize()` → `decode()` → **free a library-owned decoder immediately (before `renderAndEncode`, since decoded pixels are a standalone copy) and again in `finally` as a safety net** — `free()` is idempotent and never called on a user-injected decoder.
- **Decoder instance lifecycle**: A fresh `LibheifDecoder` is created *per conversion* (default for every entry point) so concurrent calls never share mutable WASM state. `freeSharedDecoder()` is a **no-op kept for API compatibility** — do not reintroduce a *globally shared* instance without discussion. **Sanctioned exception**: `convertMany({ reuseDecoders: true })` uses the internal `DecoderPool` (lease/return per batch runner via `acquire()`/`release()`) — each leased instance is used by exactly one item at a time and is never concurrently shared, preserving the exclusive-use invariant; the pool is module-private, opt-in, and bypassed when the caller injects `decoder`. **Fault handling**: a trap inside the module (`WebAssembly.RuntimeError`, abort) leaves emmalloc's arena unusable, so `decode()` wraps any non-`HeicConverterError` throw as `HeicConverterError('decode_failed')` (original on `cause`) and records the instance in the module-private registry in `src/wasm/fault.ts`; `DecoderPool.release()` frees a poisoned instance instead of parking it and returns its slot (a frozen count would park waiters forever once every instance had faulted). `free()` clears the mark because it drops the whole module. SECURITY.md promises typed errors — this is what makes that true rather than incidental.
- **WASM wrapper** (`build-wasm/wrapper/main.cpp`): uses embind to expose `HeicDecoder.decode(string, progressCb)`, returning `{ width, height, data, orientation?, exif? }` where `data` is a `Uint8Array` (RGBA, interleaved) and `exif` (when present) is the normalized `"Exif\0\0" + TIFF` APP1 payload from the file's Exif item. Errors are returned as strings — and because libheif builds some of them from raw container bytes (fourccs, mime types, item names), `sanitizeDecoderDetail()` strips control characters and clamps to 200 characters before the detail reaches `error.message` (which consumers log and the demo page writes into the DOM). In `src/wasm/wrapper.ts`, `LibheifDecoder.decode()` returns an **owned `Uint8ClampedArray` that is never a WASM-heap view** (copied unless the glue proves the buffer is JS-owned) — likewise `exif` is returned as an owned copy so it stays valid after `free()` — so results survive `free()` and concurrent decodes can never corrupt each other's output; `initialize()` memoizes its module-loading promise so concurrent calls load the module once. The Emscripten glue is loaded via dynamic `import()` inside `initialize()` (with tsup `splitting: true`) so it ships as a lazy chunk and stays out of the eagerly loaded bundle.
- **Orientation policy**: libheif applies `irot`/`imir` display transforms natively at decode (dimensions come back swapped), so those files must never be rotated further. The C++ wrapper reports EXIF tag 274 (`DecodedImage.orientation`, IFD0 only, bounds-checked TIFF parse with 4 MB block / 64-block caps) **only when no `irot`/`imir` fourcc appears anywhere in the container** — conservative by design: the worst case is "not rotated" (pre-0.5 behavior), never double-rotation. `convertHeic` renders the pending orientation as one composed `setTransform` matrix; resize sizing operates on display dimensions (axes swapped for 5–8). `applyOrientation: false` keeps stored geometry. Regression fixtures: `test/fixtures/exif-orientation-6.heic` (EXIF-only, stored 1600×1200 landscape — must decode `orientation: 6` and convert portrait 1200×1600) and `test/fixtures/irot-orientation-6.heic` (both signals — must decode upright with **no** pending orientation).
- **Progress callbacks**: For libheif < 1.21, `build-scripts/patch-libheif.py` patches `context.cc` with start/on/end progress hooks around tile decoding. libheif ≥ 1.21 ships these natively in `image-items/grid.cc` (grid decoding moved there), which the patch script detects and skips. `build-wasm.sh` pins 1.23.5, so the patch normally no-ops.
- **EXIF preservation policy** (`preserveExif`, default `false`): the C++ wrapper extracts the file's Exif item and normalizes it to `"Exif\0\0" + TIFF` (`DecodedImage.exif`), read **unguarded** by the `irot`/`imir` fourcc check — unlike `orientation`, which stays guarded (preserving metadata is orthogonal to display transforms). `convertHeic` re-injects the block only for JPEG (APP1 segment after APP0; payloads beyond the 65,533-byte segment limit are skipped) and PNG (`eXIf` chunk before the first IDAT, CRC32 computed in `src/render/exif.ts`); WebP/SVG ignore it. Because the rendered raster is already upright whenever the rotation was baked in (applied at render or by libheif for `irot`/`imir`), `normalizeOrientationTag` rewrites TIFF tag 274 to `1` (bounds-checked in-place copy) before injection — otherwise consumers would rotate a second time; with `applyOrientation: false` the stored geometry is kept and the tag stays verbatim. Both injectors are **fail-safe**: unparsable encoder output, malformed EXIF blocks, or size overflows return the original bytes untouched (metadata loss, never corruption) — and so does a failure to *fetch* the lazily imported `./exif` chunk, which likewise yields a conversion without metadata rather than a rejected promise — it logs a **one-time** `console.warn` naming `dist/exif-*.mjs` (test hook `__resetExifChunkWarning`), because a partial upload or a wrong MIME type must not be indistinguishable from a file that had no Exif item, and the equivalent worker failure already surfaces as `worker_load_failed`. Default-off is a privacy decision — EXIF can carry GPS.
- **AVIF capability probe**: `render/canvas.ts` probes canvas AVIF encoding once per environment (1×1 `toBlob`, module-cached promise; test hook `__resetAvifProbe`) and rejects with `format_unsupported` where unsupported (e.g. Safari). The probe is **tri-state**: `false` only for a definitive refusal (wrong blob type, empty blob, or a `toBlob` that threw/rejected), `true` for real AVIF bytes, and `undefined` when *indeterminate* — a `toBlob()` whose callback is starved (bounded by a 5-second deadline) or a `createCanvas` failure. Only booleans are cached; an indeterminate attempt clears the cache so the next call re-probes, and consumers gate on `=== false` so they never deny AVIF on a guess. `convertHeic`/`convertMany` call `assertEncodeCapability(format)` **before** paying for a decode; `renderAndEncode` keeps a defensive re-check (worker realms, engines that ignore unknown types) plus a `blob.type` re-check at encode, which is the authority in the indeterminate case. Caching a false negative was the old bug: it denied AVIF to the whole page for one starved 1×1 encode.
- **Batch/worker plumbing**: `convertMany` and `convertManyInWorker` share one bounded-concurrency runner (`src/batch.ts` `runBoundedBatch`). Abort semantics there: an aborted signal **wins over item-failure aggregation** (the batch rejects with `aborted`), while a batch that completed before the abort **wins over the late abort** (results are returned); with `continueOnError` an abort instead stops launching new items and fills not-yet-started entries with `aborted` errors. Worker-side abort terminates workers immediately; the per-URL semaphore never over-admits (a waiter cancelled while queued leaves the queue without granting its place to the next caller). Option validation is consolidated in `src/validate.ts` (`validateConvertOptions`/`validateBatchOptions`) and runs on the main thread in **all four** entry points — the worker APIs additionally validate `maxConcurrentWorkers` (positive integer) and `timeoutMs` (finite number ≥ 0) up front; `timeoutMs` is a per-call deadline that includes queue wait. The worker result message's `blob` field is widened to `Blob | string | ArrayBuffer` (field name kept for protocol compatibility; settled via `!== undefined`).
- **Bundle composition / lazy chunks**: only the main-thread in-process path is eagerly loaded — the entry plus its eagerly imported shared chunk total ~20.4 KB minified (~7.6 KB gzipped). Minification uses Terser (`tsup.config.ts` `minify: 'terser'`, `compress.passes: 3`), ~6% smaller gzipped than the esbuild default; `terser` is a dev dependency, so the package keeps zero runtime dependencies. Three modules sit behind dynamic `import()` and each ships as its own chunk: the Emscripten glue (`src/wasm/wrapper.ts` → `import('./wrapper/heic-decoder.js')`, ~34 KB after `-s FILESYSTEM=0`, first decode), the Web Worker implementation (`src/index.ts` → `import('./worker')`, ~5.7 KB, first `convertHeicInWorker`/`convertManyInWorker` call — the entry keeps thin same-named wrappers so the public API and the Promise-reject error semantics are unchanged; the wrapper also maps a *failed chunk fetch* to `HeicConverterError('worker_load_failed')` so these entry points never reject with a raw bundler/`ERR_MODULE_NOT_FOUND` error), and the EXIF injectors (`src/render/canvas.ts` → `import('./exif')` inside `withExif` *after* its `preserveExif` early return, ~2.7 KB, fetched with `.catch(() => null)` so a missing chunk degrades to no-EXIF). Because `Messages` is a single object literal that esbuild cannot tree-shake per property, worker-only message text lives in `src/messages/worker.ts` (`WorkerMessages`) rather than `src/messages/core.ts` (`Messages`) — adding a worker-only string to `Messages` moves it back into the eager chunk. **The rule is which *chunk* throws the text**, not which API it mentions: `WorkerChunkLoadFailed` belongs in `Messages` because `src/index.ts` throws it before the worker chunk exists, while `MaxConcurrentWorkersInvalid`/`TimeoutInvalid` live in `WorkerMessages` because their validators run in the worker module. `bundle.test.ts` enforces this mechanically — it extracts the string literals (including template-literal holes) from `src/messages/worker.ts` and fails if any of them appears in the built eager graph. `test/unit/bundle.test.ts` guards all of this — dynamic-edge presence in **both** the ESM and CJS builds (each format is a separate tsup pass, so one can regress without the other), a size floor per deferred chunk so a hoist-into-shared-chunk fails, a 22 KB eager budget per format, a check that every chunk a built file references is actually published, that `dist/heic-decoder.wasm` is byte-identical to `src/wasm/public/heic-decoder.wasm` (a stale `dist/` has silently shipped a wrong decoder through local verification), and ceilings on the glue chunk, the WASM and the whole first-decode payload so a size flag cannot be dropped unnoticed. Assert budgets and ceilings, never an exact byte count: the CJS tsup pass is not byte-reproducible — its eager total moves by a few dozen bytes across identical builds (currently ~21,560 raw, the tighter of the two budgets) — while the ESM eager total (20,402 raw / 7,646 gz), the glue (33,902 / 11,874 gz), the WASM and the first-decode total (314,678 gz) are stable. It skips when `dist/` is absent, **but never on CI** (`skipIf(!isBuilt && !isCI)`) — `ci.yml` builds first and asserts `dist/index.mjs`/`dist/index.js` exist, so a tsup regression that stops emitting the entry fails loudly instead of deleting every guard in the file. Do not undo these boundaries by adding a static `import` of `./worker` or `./exif` to the entry or the render stage.
- **WASM build**: `build-wasm.sh` pins `libde265 1.1.3`, `libheif 1.23.5`, and the `emscripten/emsdk:3.1.56` Docker image. libde265 ≥ 1.1.0 is CMake-only (no autotools), so it is built with `emcmake cmake`. Sources come from git submodules (`build-wasm/src/`), verified against the pinned tags before building. Both libraries **compile at `-Oz`** (`CMAKE_C_FLAGS`/`CMAKE_CXX_FLAGS`) while the **emcc link stays at `-O3`** — see "WASM size" for why that split matters. libheif is configured with `-DLIBHEIF_BOX_EMSCRIPTEN_H` (drops its dead `EMSCRIPTEN_BINDINGS` block) and every codec `option()` OFF using the names 1.23.5 actually declares (`WITH_AOM_DECODER`/`WITH_AOM_ENCODER`, `WITH_JPEG_DECODER`/`WITH_JPEG_ENCODER`, `WITH_OpenJPEG_DECODER`/`WITH_OpenJPEG_ENCODER`, `WITH_X264`, `WITH_OpenH264_DECODER`/`WITH_OpenH264_ENCODER`, `WITH_X265`, `WITH_DAV1D`, `WITH_SvtEnc`, `WITH_RAV1E`); `WITH_LIBSHARPYUV` is left at its `ON` default (inert here, never validated off). After configuring, the script **fails the build if `CMakeCache.txt` shows any third-party codec resolved** — libde265 is the sole intended one. Artifacts are copied into `src/wasm/`. Build flags that must be preserved: `-s DYNAMIC_EXECUTION=0`, `-s ALLOW_MEMORY_GROWTH=1`, `-s EXPORT_ES6=1`, `-s MODULARIZE=1`, `-s ENVIRONMENT="web,worker,node"`, `-s MALLOC=emmalloc`, `-s FILESYSTEM=0`, `--bind`, and link-level `-O3`. Cache stamps include a hash of `build-wasm.sh` itself, so editing *any* build flag forces both libraries to rebuild — a version-only stamp silently reuses archives built with the old flags.
- **WASM size (tuned in 0.5.1)**: the first-decode payload is 314,678 B gzipped / 253,450 B brotli (0.5.0: 443,427 / 332,838). Shipped levers, each runtime-validated by the real-decode suites, `test/unit/wasm-golden.test.ts` and the browser E2E: libraries compile at **`-Oz`** with the **link at `-O3`** (the module alone: 1,294,646 → 829,227 raw, 413,850 → 300,609 gz); **`-DLIBHEIF_BOX_EMSCRIPTEN_H`** removes libheif's own embind table (-5,451 gz on top of `-Oz`); **`-s FILESYSTEM=0`** leaves the module byte-identical while halving the glue (68,600 → 36,141 raw / 22,413 → 12,472 gz; 33,902 / 11,874 once the embind block is also gone) — safe because decoding is memory-only (`heif_context_read_from_memory_without_copy` in, embind RGBA out, and the lone `fopen` in `plugins/decoder_libde265.cc` is inside `#if 0`); plus `-s MALLOC=emmalloc` and a **post-link** `wasm-opt -O3 --zero-filled-memory` (-13 KB raw / -7.5 KB gz together). Final packaged binary: **812,945 raw / 295,158 gz / 235,967 br**, glue chunk 33,902 raw / 11,874 gz, eager JS 20,402 raw / 7,646 gz. Do NOT try these (all measured): asking *emcc* to size-optimize the **link** (`-O2`, `-Os`, `-Oz`, `-flto`) produces a smaller module that **fails to instantiate** — it imports a function the generated glue no longer provides (`function import requires a callable`) under `--bind` + MODULARIZE + EXPORT_ES6; note this is a *link*-level failure and says nothing about the archive compile level, which is free to be `-Oz`; post-link `--minify-imports*` would rename imports the glue already references; post-link `-Oz` and `--strip-target-features` shrink the *raw* file but measurably **increase** gz/brotli, and chaining `-Oz` with `--zero-filled-memory` cancels the zero-fill win. `-Wl,--gc-sections` collected **nothing** (module byte-identical), consistent with libheif's `box.cc` registry referencing nearly every translation unit, though note `-ffunction-sections` did not reach the libheif compiler in that probe, so it is supporting evidence rather than proof. `WITH_UNCOMPRESSED_CODEC`/`WITH_WEBCODECS`/`WITH_HEADER_COMPRESSION` genuinely default OFF; `WITH_LIBSHARPYUV` defaults ON. Remaining levers are small: the *entire* glue chunk is now 11,874 gz, so a hand-rolled C-ABI replacement for embind can never be worth more than that. Re-measure everything against a newer emsdk before chasing more.
- **Env detection**: `render/canvas.ts` supports `OffscreenCanvas` first, then `HTMLCanvasElement`, and throws a clear error in environments with neither. Node users decode raw RGBA via `LibheifDecoder` and encode externally (e.g. `sharp`).

## Conventions

- **Commit messages must follow Conventional Commits** (`feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert`, optional scope). Enforced by the husky `commit-msg` hook; `pre-commit` runs the linter and `npm run typecheck`. Example: `feat(wasm): add progress callback support`.
- TypeScript, strict-ish typed code; keep public API surface small and backwards compatible (e.g. `freeSharedDecoder` kept as a no-op).
- Unit tests live in `test/unit/**/*.test.ts` and run in a Node environment with Vitest. Coverage thresholds are configured in `vitest.config.ts`. **Tests are typechecked too** (`tsconfig.test.json`, which must keep overriding the base config's `exclude: ["test"]` or the project is silently vacuous) — the tests were excluded from `tsconfig.json` outright before, and that hid real defects (worker tests passing `format:`/`'arraybuffer'`, which are not option names).
- **Documentation that duplicates a code fact is tested, not trusted**: `test/unit/readme.test.ts` parses the `HeicConverterErrorCode` union out of `src/errors.ts` and the README's `code` table out of `README.md` and requires them to match exactly (and the table rows to stay contiguous); the public JSDoc for `convertHeicInWorker`/`convertManyInWorker` lives on the wrappers in `src/index.ts` because that is what `dist/index.d.ts` ships — the implementation's comments in `src/worker.ts` never reach a consumer.
- CI (`.github/workflows/ci.yml`) runs `npm ci` → gates (`verify:wasm`, `check:scripts`) → `npm run lint` → `npm run typecheck` → `npm run build` → `npm run test:coverage` (thresholds enforced) → `npx playwright install chromium` → `node test/browser/test-playwright.mjs` (browser E2E: real conversions against the CSP sandbox and the GitHub Pages demo) on pushes/PRs to `main`. The GitHub Pages demo (`.github/workflows/demo-pages.yml`) builds `docs/` + `dist/` into a site artifact and deploys it from `main`. `publish.yml` is split so the token-holding job never installs dependencies: `verify` (no `id-token`) does `npm ci` + gates + build + coverage and uploads `dist/`; `publish` (`needs: verify`) downloads those exact bytes, requires the tag to equal the version **and** be an ancestor of `main`, publishes with `--registry` pinned on the CLI, then runs `npm run verify:provenance` against the registry.

## Gotchas

- **Never edit generated files**: `src/wasm/wrapper/heic-decoder.js`, `src/wasm/public/heic-decoder.wasm`, or anything in `dist/` / `build-wasm/src/` (submodule C++). Regenerate via `npm run build:wasm` instead.
- **Submodule drift**: `build-wasm.sh` verifies the `build-wasm/src/` submodules are checked out at the pinned tags and fails with a hint if they drift. Bump `LIBDE265_VERSION`/`LIBHEIF_VERSION` **and** `git checkout` the new tag in the submodule; if the `src/wasm` artifacts look unchanged after a bump, check the submodule commit.
- **`npm run build:wasm` requires Docker and network access** (fetches submodules on first checkout). It takes a long time; only run it when changing `main.cpp`, the build script, or lib versions.
- **Two separate "builds"**: `build` (TS → `dist/`) and `build:wasm` (C++ → WASM). Most frontend work only needs `npm run build`.
- `.wasm` is externalized from the main bundle (`tsup.config.ts` `external`) and served separately; changing how it's located/loaded must stay compatible with `locateFile` and `wasmBinary` options.
- Tests that decode real HEIC files require the built WASM artifact — run `npm run build:wasm` (or ensure `src/wasm/public/heic-decoder.wasm` exists) before running integration tests.
- **WASM build changes must be executed, not just measured.** Every size flag rejected in 0.5.1 built cleanly and produced a *smaller* `heic-decoder.wasm`; they only failed at `WebAssembly.instantiate()` in `test/unit/integration.test.ts`. Compare artifact sizes all you like, but adopt nothing until the real-decode integration tests, `test/unit/wasm-golden.test.ts` (exact decoded RGBA per fixture + the mutated-input outcomes and error codes) and the browser E2E suite pass against the rebuilt pair (`src/wasm/public/heic-decoder.wasm` + `src/wasm/wrapper/heic-decoder.js` come from one `emcc` invocation — always replace them together, then `npm run wasm:hashes`).
- **Never deep-compare large buffers in tests.** `expect(a).toEqual(b)` on two ~800 KB Buffers walks them structurally rather than with `memcmp` — measured ~1.1 s idle and *over the 5 s test timeout* under the parallel suite, which made `bundle.test.ts`'s stale-`dist` guard flake. Compare with `a.equals(b)` and put a `sha256` of each side in the failure message; for pixel data, hash and compare digests (what `wasm-golden.test.ts` does) instead of comparing arrays.
- **The real-WASM suites must never be able to skip green.** `test/unit/integration.test.ts`, `test/unit/decoder.test.ts` and `test/unit/wasm-golden.test.ts` all skip when `dist/heic-decoder.wasm` or a fixture is missing *outside* CI, and run unconditionally (failing) when `CI` is set. Per-test `it.skipIf` is not sufficient: when every test in a suite is skipped, `beforeAll` never runs and vitest exits 0 — that hole let the entire 35-test real-decoder suite vanish green on CI. Keep the `describe.skipIf(!hasArtifacts && !isCI)` shape and keep `ci.yml`'s artifact `test -f` checks in sync with whatever `hasArtifacts` requires.
- **Never put a double quote inside the `bash -c "..."` block in `build-wasm.sh`.** The whole container script is one double-quoted string, so an unescaped `"` (even in a comment) truncates it — `docker` still exits 0, `bash -n` still passes, and the build silently stops before the link. The script now requires a `Build complete!` sentinel in the container output, so a truncated run fails loudly. Use single quotes inside that block.
- Keep the library environment-agnostic at import time: no top-level browser-only references (e.g. `document`, `Blob` usage is guarded).
- **Never disguise a string to silence a scanner.** Scanners report three signals on this package and all three are correct-but-harmless: `Network access` (the generated Emscripten glue `fetch()`es `heic-decoder.wasm`), `URL strings` (the `http://www.w3.org/2000/svg` XML namespace in SVG output), and `Minified code` (Terser output on purpose). Concatenating a literal into fragments, hex-encoding it, or renaming it to dodge a heuristic is how malware behaves and how a maintainer loses trust — document it in the README's _Supply chain & trust_ table instead, and change the code only when the signal describes something actually wrong.
- **Dev-tree install scripts are the only code-execution surface here** (the package has no runtime dependencies). `npm ci --ignore-scripts` is not usable because esbuild's postinstall links its platform binary, so the set of packages declaring `preinstall`/`install`/`postinstall` (or shipping a `binding.gyp`) is pinned by **name *and* version** in `build-scripts/install-scripts.json` and CI fails on drift — a new release of an allowlisted package is an unreviewed code execution and must be re-reviewed deliberately. Non-registry resolutions (`file:`/`link:`/git) are rejected outright. When a legitimate dependency is added: read its script, then `npm run check:scripts -- --write` and commit the diff.
- **`tsconfig.test.json` must keep its own `exclude` line.** It extends `tsconfig.json`, which excludes `test/`; without the override the test project inherits that exclusion and `npm run typecheck` silently checks nothing (verified by canary: an injected type error stayed green until the override was restored).
- **A falsification that terser can delete is not a falsification.** When proving the bundle guard bites, inject the leaked text on a *live throw path* (e.g. inside a validator's `throw`), not as dead code like `void WorkerMessages.X` — minification removes the latter and the assertion passes vacuously while appearing to test the boundary.
- **Always `npm run build` before running suites after a checkout or merge.** A `dist/` from an older commit pairs a stale JS chunk with the current WASM and surfaces as the misleading `module.HeicDecoder is not a constructor`; `bundle.test.ts`'s byte-identity check compares the WASM against `src/`, not the JS chunks against `src/`.
